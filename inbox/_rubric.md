# 储能结构周报 · 写作与审核清单（rubric）

本文件是「三专家写作回路」里**审核专家唯一使用的判定尺子**。每周同一把尺子，不临时加要求、不靠形容词。
写稿前先读，审核时逐项打 PASS / FAIL；任一项 FAIL 即退回。

- 适用对象：`inbox/<YYYY-MM-DD>.md`（当期正文，从 `## 一、` 起）
- 参照物：`docs/2026-11-02.md`（排版 ground truth）、`pushed_history.json`（去重基准）、`inbox/_disclosures.md`（机型已披露维度）
- 修改本文件需同步修改 `main.py` 的 `ROLE_AND_RULES`；两者不一致时以本文件为准并立刻对齐

---

## 回路与退回（收口规则）

```
基准载入 → 资源检索 → 格式撰写 → 审核 ─┬─ PASS → 本地 dry-run 闸门 → 投递
                                        ├─ 退回 A（内容缺项）→ 资源检索
                                        └─ 退回 B（格式/口径）→ 格式撰写
```

1. **只有审核专家有权退回**，退回必须写明去向（A 或 B）和**具体缺口清单**。禁止写「内容不足」「再完善一下」这类无法执行的结论。
2. **退回到检索时，必须列出「要补的具体缺口」**（例：板块一缺 2026-11-04 BLUETTI Apex 200 正式上市的第三方实测；板块三缺结构件材料侧的牌号或工艺参数），而不是「再搜一遍」。
3. **退回上限 2 轮**。第 2 轮仍 FAIL，不再硬凑，按「本周期未检索到可核实进展」如实写缺口。
   > 理由：本项目本地没有 URL / 数字校验层（见 `CLAUDE.md` 硬性约束 7），硬凑出的条目比空白危险得多。
4. 审核结论必须落成 `inbox/_review-<YYYY-MM-DD>.md`（PASS/FAIL 逐项 + 退回记录），不允许只在对话里口头通过。

## R1 · 内容完整性

| # | 判定项 | PASS 标准 | FAIL 触发 |
|---|---|---|---|
| 1.1 | 五板块齐全 | 一至五全部存在，且每个板块都有实质内容（或按 1.8 如实写缺口） | 缺任一板块；板块只有标题没有正文 |
| 1.2 | 条目密度 | 每条含 4~7 个 `- **标签**：内容` 分点 | 分点少于 4 或多于 7；用大段散文替代分点 |
| 1.3 | 来源可核 | 每条有 `**来源**：` 行，≥1 个指向**该条事实**的原文链接 | 只有列表页 / 栏目页 / 标签页链接；来源指向首页；链接打不开 |
| 1.4 | 数字有出处 | 每个参数（容量、功率、重量、尺寸、循环、效率、防护等级、价格）都能在来源原文里找到 | 数字与原文不一致；出现来源中不存在的数字；单位错 |
| 1.5 | 板块三双向覆盖 | 电芯/体系侧与**结构件材料侧**都判过一轮（钣金、注塑、压铸、挤出、结构胶） | 只写电芯就交付；未判结构件侧直接跳过 |
| 1.6 | 板块四按地区 | 固定 `**北美**` / `**欧洲**` / `**日本**` 三组，每组覆盖认证、政策、安装维护 | 缺地区组；每组只有一句空话 |
| 1.7 | 板块五可执行 | 3 条编号建议，点名 Jackery 具体产品线（Explorer / HomePower / SolarVault / SolarSaga / FridgeGuard） | 泛泛而谈；没有落到具体产品线 |
| 1.8 | 缺口如实写 | 无进展时写「本周期未检索到可核实的…」并附官方入口链接 + `**特点**` | 用占位句凑数；把「没搜到」写成「没有变化」 |
| 1.9 | 不写自家新品 | 板块一至板块四不出现 Jackery 自家新品 | 板块一出现 Jackery 新品播报 |
| 1.10 | 中英双向检索已做 | 检索日志里能看到中文源与英文源都覆盖，且点名厂商（含大疆）都查过 | 只有英文源；中文厂商（大疆、海辰、派能、亿纬、阳光）系统性缺失 |

## R2 · 格式合规

| # | 判定项 | PASS 标准 | FAIL 触发 |
|---|---|---|---|
| 2.1 | 板块标题逐字固定 | `## 一、便携&阳台储能竞品动态`、`## 二、户用&工商业储能与大机动态`、`## 三、电池与材料技术突破`、`## 四、安规与政策大事件`、`## 五、对华宝新能（Jackery）结构与产品定义的启发` | 标题加空格、改字、换顺序 |
| 2.2 | 条目四段式 | `### N. **厂商** —— 一句话标题` + 分点 + `**来源**：… ｜ …` + `**特点**：…` | 缺任一段；`### ` 用成 `#### ` |
| 2.3 | 序号重排 | 每个板块内从 1 开始重排 | 全局连续编号 |
| 2.4 | 板块四禁用小标题 | 地区名是独立加粗行 `**北美**` | 出现 `### 北美` 之类（会让整区进入可删除集合，属安全边界） |
| 2.5 | 特点句克制 | 只归纳本条已列信息；不引入新数字、新事实、新链接；不写「值得关注」「意义重大」；不重复标题 | 特点句出现来源外数字或评价性空话 |
| 2.6 | 只用受支持的 Markdown | 段落、`- ` 列表、`### `、`## `、`**加粗**`、`[文字](URL)` | 引用块 `>`、表格、图片、HTML 标签、脚注（渲染器不覆盖，会静默降级） |
| 2.7 | 无转义残留 | `$`、`~`、`_`、`*` 原样，不出反斜杠 | 出现 `\$`、`\~`、`\_` |
| 2.8 | 列表符号统一 | 一律 `- ` | 出现 `* `（编辑器自动格式化常见产物） |
| 2.9 | 无一级标题与覆盖周期行 | 文件从 `## 一、` 开始，header 由本地 `_finalize_report` 生成 | 稿子里自带 `# ` 标题或「覆盖周期」行 |
| 2.10 | 数额与区间写法 | `−20~+55 ℃`、`€1,249`、`6,028 Wh` 这类可直接喂给渲染器 | 全角/半角混用导致渲染错位；数字与单位之间混乱 |
| 2.11 | 署名一行 | 文末 `—— 本消息由自动化脚本生成并推送，检索与撰稿由 Doubao 完成` | 署名写成 Perplexity / OpenRouter |

## R3 · 去重与新披露

| # | 判定项 | PASS 标准 | FAIL 触发 |
|---|---|---|---|
| 3.1 | 与台账比对 | 每条都已对照 `pushed_history.json` 的 45 条标题判过 | 直接重写上一期条目 |
| 3.2 | 聚合页排除 | 引用的是具体报道页 | 引用栏目页 / 标签页（会永久误杀引用它的所有条目） |
| 3.3 | 新披露判定 | 同机型如满足下面「三入口」之一，**允许**作为本期新条目 | 同机型只重复旧信息 |
| 3.4 | 排除项拦截 | 「四类排除」内容不进稿 | 把价格 / 促销 / 开卖日期 / 页面改版当新披露 |
| 3.5 | 必须引新链接 | 新披露条目引用的链接不在台账里（否则代码层整块删除） | 只引上期那条旧链接 |
| 3.6 | 同厂商连续排布 | 同一厂商多条在板块内相邻 | 同一厂商被拆到板块两端 |

### 「新披露」三入口（满足任一即可作为本期新条目）

1. **首次公开的规格 / 结构参数**：容量、功率、重量、尺寸、循环寿命、效率、防护等级、热管理方式、扩展拓扑。
2. **第三方拆机与实测**：teardown、拆解、热成像、循环实测、温升 / 噪音实测、结构件材料或工艺披露。
3. **认证与合规状态变化**：UL / NFPA / EU 电池法规 / 日本消防与电气事业法口径的实际变动。

### 「四类排除」（不构成新披露，出现即 FAIL）

1. 价格变动与早鸟 / 限时折扣。
2. 促销、套装、优惠码。
3. 开卖 / 预售 / 上架 / 渠道铺货日期（除非同时给出新规格）。
4. 官网页面改版、"updated" 时间戳变化而无新内容。

> 判定口诀：**能不能回答「这台机器做起来有什么不同」**。答不上来，就是商业消息，不是情报。

## R4 · 已知失败模式（命中即 FAIL，优先于上面所有项）

| 失败模式 | 症状 | 该怎么做 |
|---|---|---|
| 促销稿混进板块一 | 「进入上市促销 / 限时优惠」，容量与价格都真，但原文只在打折 | 删；不要把商业消息当新品 |
| 板块四长出 `### ` | 地区名写成小标题 | 改回 `**北美**` 粗体行 |
| 中英检索写成单边 | 某厂商整条静默消失 | 补中文源，先查促销误杀与台账去重，再改检索 |
| 自家产品进板块一~四 | 出现 Jackery 新品 | 删；板块五是唯一谈自家产品的地方 |
| 硬凑缺口 | 板块三结构件侧长期空白就想动 prompt | 先确认关键词覆盖，再判断是否真没有 |
| 格式化工具有外改稿 | `- `→`* `、`$`→`\$`、标题加空格 | 整篇还原，并对 `inbox/` 关掉编辑器自动格式化 |

## 交付前必经闸门（不花额度）

```powershell
Set-Location -LiteralPath "D:\资讯推送"
& ".\.venv\Scripts\python.exe" main.py --from-report "inbox\<YYYY-MM-DD>.md" --dry-run
```

必须全绿：五板块齐全非空、促销剔除 0、跨周重复剔除 0（非 0 要逐条解释）、`[行业资讯]` 已出现、摘要 1 条、退出码 0。

投递后可选复核（不花额度）：

```powershell
& ".\.venv\Scripts\python.exe" main.py --rebuild
```
